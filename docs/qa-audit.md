# Vapor QA audit

Date: 2026-10-03. Scope: renderer (`src/renderer/src/**`), IPC contract, main-process handlers, downloads, library, tray and the Epic provider. Method: a full code read, plus hands-on testing in the browser mock (`npm run dev:web`, at 1400x860 and at the 1000x640 minimum window size, in these modes: default, `?mock=many`, `signedout`, `empty` and `loading`). Read-only: no source files were changed.

> Other people were editing files during the audit (for example, a "local games" provider, artwork and shortcuts were being added to `main/index.ts` and `devMock.ts`). Line numbers are correct as of the audit and may have moved since. Search for the quoted snippet if a line doesn't match.

## Summary

The UI is well built. Almost every control is wired to a real IPC handler, most failures show a toast through `act()`, and the Steam-like flows (queue, graphs, properties, DLC, context menu with submenu flipping, keyboard navigation in the sidebar) work in the mock. The serious problems are:

- **One crash (P0):** opening the Store with a target URL before the `<webview>` is ready throws synchronously inside a React effect. The app has no error boundary, so the whole window goes blank. This happens on the first click in a session of *View in store*, a *Free games* card, or *Games → Free games this week*.
- **Destructive actions with no guard:** Cancel and Remove in Downloads delete partial installs without asking. *Locate existing install…* adopts any folder, and a later Uninstall `rm -rf`s it.
- **Races and stale state:** Play can launch a game twice. An expired session leaves the UI saying "signed in". The install dialog navigates to Downloads even when the install failed.
- **Third-party (EA/Ubisoft) titles:** the install path goes through a manifest-based plan that it doesn't need, then sends you to an empty Downloads page.
- **Performance:** `App` subscribes to the whole store, so every download tick (4 per second) re-renders the whole tree. With 600 games I measured 50–64 ms main-thread stalls per tick (dev build).

**Counts: P0 = 1, P1 = 12, P2 = 46 (59 total).**

## Issues

Severity: **P0** broken / crash · **P1** wrong behaviour, data risk or a misleading state · **P2** polish, edge case or minor.

### P0

| ID | Area | File:line | What's wrong | Repro | Suggested fix |
|---|---|---|---|---|---|
| P0-1 | Store / app shell | `views/StoreView.tsx:89-104` (`if (target) go(target)`), `App.tsx:25-27` | On first mount, `StoreView` calls `webview.loadURL()` from an effect before the guest is attached. - Ownership-aware Free Games shelf ("In library" or "Claimed" badges).
- A Friends/presence equivalent, or at least a real online/offline indicator (P2-26).
- An in-app overlay and controller or Big Picture-style navigation (low priority).
